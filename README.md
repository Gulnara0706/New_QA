## Переменные окружения

Риски на уровне UI/UX:
Некорректное отображение сообщения: текст искажается (обрезается, появляются артефакты), форматирование ломается.

Проблемы с порядком сообщений: новые сообщения появляются не в конце ленты, а в середине или начале.

Дублирование в интерфейсе: клиент отображает сообщение дважды, хотя сервер создал только одну запись.

Задержка отображения: сообщение отправлено и получено сервером, но не появляется в ленте в течение нескольких секунд.

Отсутствие индикаторов состояния: нет индикаторов загрузки во время отправки, ошибок при неудаче.

Нечитаемые сообщения: проблемы с отображением эмодзи, специальных символов, длинных строк или текста на разных языках.

Проблемы с прокруткой: после отправки сообщения лента может не прокручивается к новому сообщению автоматически.

Ошибки локализации: тексты ошибок или уведомлений отображаются на неверном языке.




Риски на уровне взаимодействия клиент‑сервер:
Потеря сообщений при сетевых сбоях: сообщение не сохраняется локально при потере соединения, теряется безвозвратно.

Игнорирование идемпотентности: клиент отправляет повторный запрос с тем же txnId, но не проверяет, что сервер вернул тот же event_id.

Таймауты без обратной связи: запрос зависает, клиент не показывает ошибку и не даёт возможности повторить отправку.

Конфликтующие запросы: параллельная отправка нескольких сообщений приводит к ошибкам или нарушению порядка.

Некорректный txnId: клиент генерирует не уникальные или некорректные txnId, что нарушает идемпотентность.

Потеря ответа сервера: сервер обработал запрос, но ответ не дошёл до клиента — сообщение не отображается, хотя существует на сервере.


Риски на уровне API и сервера :
Нарушение идемпотентности на сервере: повторный запрос с тем же txnId создаёт дубликат сообщения.

Некорректные ответы сервера: сервер возвращает 200 OK, но не создаёт сообщение.

Неожиданные HTTP‑статусы: сервер возвращает нестандартные статусы.

Ограничения сервера:

лимит на длину сообщения не документирован, сервер обрезает текст без уведомления;

ограничение на частоту запросов (rate limiting) вызывает ошибки без предупреждения.

Риски производительности:
Высокая нагрузка на клиент: обработка большого количества сообщений (тысячи) тормозит интерфейс.

Медленная синхронизация: после перезагрузки страницы лента загружается долго, новые сообщения не появляются сразу.
